## Touchpoint highlights

**November 11: The Infrastructure Factory.** Max Körbächer opened our show-and-tell series with a platform that turns requests from humans or agents into ready-to-use environments, with an MCP server as the front door and agentgateway as the policy gate. The DevRel takeaway: with environments on request, hackathon and workshop participants start with the project, not with installation steps. The session closed with a message for our profession: your next developers are also agents. [Read the recap](/blog/2026/infrastructure-factory-show-and-tell).

**November 18: Touchpoint Review Team sync.** Five community volunteers met to design an open process to select show-and-tell sessions, so that topic decisions do not sit only with Linux Foundation staff. The group agreed that every session must connect clearly to DevRel responsibilities, challenges, or evolving roles. [Read the public meeting notes](https://github.com/DevRel-Foundation/governance/discussions/185).

What came out of that call:

- **Reviews now happen in the open with GitVote.** Reviewers vote on GitHub issues, and each submission is mirrored from the form without the speaker's name, email, or affiliation. The [first submission](https://github.com/DevRel-Foundation/governance/issues/184) passed, with a request to the submitter to make the DevRel angle stronger.
- **The submission form now asks better questions.** The [updated form](/community/touchpoints/submit) asks which DevRel challenge a session addresses and what practical takeaway attendees get, and speakers confirm that the session is not a sales or product pitch ([pull request](https://github.com/DevRel-Foundation/site/pull/118)).
- **The session list is public.** Every scheduled show-and-tell session now has its own page in the [governance repository](https://github.com/DevRel-Foundation/governance/tree/main/touchpoints).

> Do you have a workflow, a tool, or an experiment to share? Sessions run from 5 to 30 minutes, and work in progress is welcome.

## Help shape a DevRel track at Open Source Summit 2027

There is an opportunity to have a DevRel track at Open Source Summit North America, Europe, and Japan in 2027. The idea is to bring the spirit of our Touchpoints to an in-person setting: practitioners sharing their work, discussing common challenges, and learning practical approaches from each other. Touchpoint participants who review show-and-tell submissions have committed to help draft the track description and to be part of the CFP review team.

The draft proposes three sub-themes:

- **Evolving DevRel skills:** what practitioners need to learn as AI changes developer workflows and expectations
- **Demonstrating DevRel's value:** measuring impact when agents mediate the developer journey
- **Adapting DevRel programs:** serving developers and their agents while keeping developer needs central

We want your input on three questions. Which everyday challenges should the CFP cover? Does the description capture what makes a talk relevant to DevRel professionals? Which regional or language needs should we consider across the three events?

[Comment on the discussion](https://github.com/DevRel-Foundation/governance/discussions/186), or bring your ideas to the November 25 and December Touchpoints.

## Ideas in progress

**A framework for project donations.** DRF has no documented process to evaluate an offer to transfer an existing project to the Foundation. The community has started to design a lightweight one, based on how DRF projects such as the Metrics Index and the Persona Library started and on how larger Linux Foundation communities evaluate donations. [Follow the discussion](https://github.com/DevRel-Foundation/governance/discussions/174).

**The 2027 DRF Unconference.** Community members are planning a virtual unconference to set the Foundation's priorities for 2027. Anyone can propose a topic, but only if they can commit to work on it, and the topics with the most votes get scheduled. Current drafts include [bringing end user economics to DevRel](https://github.com/DevRel-Foundation/governance/discussions/172), [project donations](https://github.com/DevRel-Foundation/governance/discussions/174), and [DevRel skills in agent-assisted development](https://github.com/DevRel-Foundation/governance/discussions/175). [See how the unconference works](https://github.com/DevRel-Foundation/governance/discussions/173) and [vote on topics](https://github.com/DevRel-Foundation/governance/discussions/categories/2027-drf-unconference).

**Show us your agent-assisted workflow.** The call for show-and-tell sessions is still open: demos that update when a product ships, talk recordings turned into tutorials, workshop materials that test themselves, recurring metrics reports. Things that did not work are useful to hear about too. [Share yours in the discussion](https://github.com/DevRel-Foundation/governance/discussions/178).

**A clearer Code of Conduct for Discord.** The governance repository now [states how the Code of Conduct applies](https://github.com/DevRel-Foundation/governance/pull/182) on the DRF Discord server. [Join the conversation on Discord](https://discord.gg/G7CSTKZcuT).

## Worth reading

Articles from outside the Foundation about DevRel practice, agents, and developers.

- **[Is Software Dead? Part Four: Developer Relations](https://dev.to/kate_astrid/our-docs-have-a-new-reader-and-it-skips-straight-to-the-code-3l9h)** (Kate Astrid, October 26). Coding agents are a second audience for documentation, and they skip the narrative that human readers value. DevRel should make docs work for both, and measure success by completed tasks.
- **[How to improve developer experience for humans and AI agents](https://hackmamba.io/developer-relations/how-to-improve-developer-experience/)** (Hackmamba, October 30). Ten practical steps for developer experience and agent experience. It cites [Mintlify's 2026 State of Knowledge Report](https://www.mintlify.com/state-of-knowledge/2026), where agents made 66% of requests to hosted docs in August.
- **[AI slop is piling up highest on the biggest open-source projects](https://www.helpnetsecurity.com/2026/10/26/linux-foundation-open-source-ai-slop/)** (Help Net Security, October 26). A Linux Foundation survey of 234 contributors and maintainers: about one in four incoming changes is low quality or AI-generated, and few projects have formal rules. Useful context for anyone who runs a contributor program.
- **[GitHub Agentic Workflows is generally available](https://github.blog/changelog/2026-10-28-github-agentic-workflows-generally-available)** (GitHub, October 28). Coding agents inside GitHub Actions for issue triage, documentation updates, and more, defined in Markdown. One of the tools behind our [call for workflows](https://github.com/DevRel-Foundation/governance/discussions/178).
- **[Beyond code generation: A developer's guide to agentic engineering](https://github.blog/ai-and-ml/github-copilot/beyond-code-generation-a-developers-guide-to-agentic-engineering/)** (GitHub, November 6). Writing code got faster, but the work around it did not. A walkthrough of plan, build, verify, and observe, and where human judgment still matters.
- **[DevRel metrics: how to measure developer relations ROI](https://hackmamba.io/devrel/devrel-metrics/)** (Hackmamba, November 11). Activation, retention, and pipeline metrics for reports to leadership. A good starting point for the "Demonstrating DevRel's value" sub-theme above.
- **[Introducing Scope: Open-source evaluation for AI coding agents](https://opensource.microsoft.com/blog/2026/10/19/introducing-scope-open-source-evaluation-for-ai-coding-agents/)** (Microsoft, October 19). Repeatable experiments to test how coding agents find and use your APIs, SDKs, and docs. Good preparation for the December 16 Touchpoint.
